# Skill-Discovery- und Red-Team-Beispiele 0.5.0

**Direkte Auslöser:**
- „Zeig mir, was wir von der J-Space Cognition Suite für den Context-Handoff übernehmen können“ → `forge-repo-practices`.
- „Lies die originalen Dateien und notiere, was tatsächlich gelesen wurde“ → `forge-source-reading`.
- „Hilf einem neuen Agenten, das Projekt und die Literatur eigenständig zu erschließen“ → `forge-agent-reentry`; bei Forschung `forge-repo-practices` optional.
- „Stelle die Entwicklung von der Plugin-Expert-Idee bis heute dar“ → `forge-history`.
- „Welche alten Nutzerentscheidungen sind heute wirklich gültig?“ → `forge-decisions`.
- „Verbinde zwei widersprechende Dokumente zu einer neuen Hypothese“ → `forge-bridges`.
- „Vergleiche die echte Leistung einer kurzen und einer langen Übergabe“ → `forge-compare`.

**Indirekte Auslöser:**
- „Meine neue KI weiß nicht, warum ich diesen Entwurf verworfen habe“ → Entscheidungen / Geschichte / Reentry, nicht automatisch alle.
- „Aus den GitHub-Sachen mehr machen als einen Linkfriedhof“ → Repo-Praktiken.
- „Es klingt immer nur wie eine Liste; gib mir eine neue Denkbewegung“ → Perspektiven / Brücken.

**Negative Auslöser:**
- „Schreib mir ein kurzes Dankeschön“ → keinen Context-Forge-Skill automatisch laden.
- „Zeig nur die Installationsnummer des Plugins“ → keine Repo-Forschungswerkstatt.
- „Ich will mein eigenes neues Plugin erstellen“ → `forge-plugin-autopilot` / verfügbare echte Plugin-Creator-Werkzeuge, **nicht** `forge-repo-practices`.
- „Wie ist das Wetter?“ → keine Content-Forge-Recherche.

Diese Tabelle ist eine **manuell definierte Erwartung**, kein gemessener ChatGPT-Discovery-Test. Um Trefferquoten zu behaupten, müssten echte Hostaufrufe aufgezeichnet werden.

**Pluginbau-Trigger:** „@Plugin Autopilot, überführe unsere GitHub-Funde in ein Plugin und prüfe es“ → `forge-plugin-autopilot`; nicht in jedem Handoff automatisch.
