# Die drei untersuchten GitHub-Quellen: von realer Implementierung zur eigenen Fähigkeit

**Stand des hier erfolgten direkten Abrufs: 17.10.2026, GitHub-Konnektor.** Die angegebenen Blob-SHAs beziehen sich auf die konkret gelesenen Dateien der damaligen Default Branch, nicht auf ein für alle Ewigkeit fixiertes Commit. Wir übernehmen Arbeitsprinzipien und implementieren eigene, deutlich begrenztere stdlib-Helfer. **Es wurde kein fremdes Repository als Ganzes vendort oder heimlich installiert.** Ein solcher Codeimport würde Abhängigkeiten, Lizenzen und Sicherheit erneut prüfen müssen.

## 1 · J-Space Cognition Suite

- Repository: https://github.com/Tiger3807861189/J-Space-Cognition-Suite
- Gelesen: `README.md`, `j-space/SKILL.md` (Blob `a46e49aa3197c9d83d0e790933ff0e3ae83e7e83`), `j-space/modules/repository.md` (Blob `13956e71ceb20aa0e28cddb5227a2113c049ab12`), `j-space/references/controller.md` (Blob `5e857d32f8b1f37fcd5929924cae27bc6d01702b`), Lizenz Apache-2.0.
- Echte Quelleigenschaft: **Ein einziger J-Space-Einstieg** lädt bei Bedarf bis zu 13 spezialisierte Module. `control.py` unter Python 3.10+ verwaltet Quell-Fingerprints, gezieltes Wiederlesen, Ereignisse an Aufgabenübergängen und verifizierbare Prüfbedingungen, wenn er vom Host ausdrücklich gerufen wird; die Suite kann keine Host-Hooks selbst erschaffen. Eine semantische Projektkarte ist mit tatsächlichen Quellen verbunden; ein Hash allein beweist ihre Interpretation nicht.
- **Tatsächlich in Context Forge eingebaut:** statt 17 aktivierbarer Skills **ein** Hauptskill; Referenzen als bedarfsweise Organe; `case_engine.py` für gemeinsame eindeutige Quellen-/Aussagekennungen, exakte Originalfundstellen, Quelle-Fingerprints, Korrektur- und Beziehungserfassung, verifizierbare Wiederaufnahme. Kein Kopieren des originalen Controllers, keine behauptete Agentendelegation.
- **Wichtigste Nutzung:** Lange Handoffs und Projektentwicklung, in denen verschiedene Phasen dieselbe ursprünglich gelesene Aussage anders bewerten können, ohne sie neu zu erfinden.

## 2 · sina-gpt

- Repository: https://github.com/sina85/sina-gpt
- Gelesen: `README.md` (Blob `35f0546b3ea26a27b561d474577d6eb31dfd79c9`), `specs/j-space-reasoning-objective.md` (Blob `27ee2cd9c01258ce509e82014db52792a9db74cc`), `specs/sina-loop-v2-jspace-workflow.md` (Blob `693a93afee35a7280ef469612ceda10b0592b3cf`), `research/stage0/README.md` (Blob `d9b8015be0f6c79aad512588bcd34fb3164cb97e`), Lizenz MIT.
- Echte Quelleigenschaft: Forschungsprojekt zur **Veränderung und Messung interner Repräsentationen durch Modelltraining**, kein allgemeiner ChatGPT-Skill. Der im README erklärte v2-Prozess trennt vorher fixierte Testbatterie, Lehrermodell- und Studentenläufe, J-Lens-Auswertung, gezielte Trainingsvariation und nachträgliche Gegenprüfung. Der aktuelle Stand wird teilweise ausdrücklich als **noch zu bauende Pipeline** dokumentiert; insbesondere dürfen die 512/1.536 Probeentwürfe nicht pauschal als vollständig eingefrorene, geprüfte Messung ausgegeben werden.
- Entscheidender übersetzbarer Mechanismus: **Drei kontrastierende Versionen einer Fragestellung**: Baseline, relevante Veränderung mit erwartbar anderem Ergebnis und irrelevante Paraphrase mit erwartbar gleichem Ergebnis. Das verhindert, dass eine Evaluation nur hübsch formulierte Einfälle belohnt. **Freeze mit SHA vor der Antwortbeobachtung**, anschließend vergleichbare Läufe, getrennte Urteile.
- **Tatsächlich eingebaut:** `case_engine.py freeze-probes` und `score-probes`. Die Befunde betreffen nachweisbare Antworten eines Zielagenten auf definierte Texte. Es werden keinerlei Studentengewichte trainiert oder J-Space-Aktivierungen bewertet. Besonders geeignet, um bei einer Masterprompt-Überarbeitung zu testen, ob ein Agent durch echte Nutzerkorrektur seine Entscheidung ändert, durch bloßes Umformulieren aber nicht.

## 3 · jlens-gguf

- Repository: https://github.com/igorbarshteyn/jlens-gguf
- Gelesen: `README.md`, `QUICKSTART.md` (Blob `dee81a83b60f46723da43c887964106a97487aeb`), `jlens_gguf/server.py` (Blob `dd2dc7efb0c7c143c0618f3bca7c876f022528dc`), `pyproject.toml` (Blob `315abc83b6ec9cdcbc6c339f59875fd5463bdd81`), Lizenz Apache-2.0.
- **Was wirklich existiert:** Ein lokales Python/Numpy-Frontend sowie ein nativer llama.cpp-kompatibler GGUF-Aktivierungsserver mit `GET /api/props`, `POST /api/slice`, `/api/readout`, `/api/generate` und anderen Routen. Geeignete Umgebungen können Eingriffsvarianten **steer**, **swap**, **ablate** untersuchen und baselines vergleichen. Dies ist eine eigene Model-Serving-Laufzeit, kein Zugriff auf internes ChatGPT. Eine GGUF-native per Ridge Regression *gefitte* Linse ist zudem ein **korrelationales Näherungsverfahren**, nicht automatisch die kausal per Backprop ermittelte Jacobian Lens.
- **Tatsächlich eingebaut:** Ein stdlib-Loopback-Client `scripts/jlens_local.py` für echte GET `/api/props` und POST `/api/readout` auf einem vom Nutzer selbst bereitgestellten, laufenden lokalen J-Lens-Server (keine native Laufzeit installiert oder gestartet). Daneben ein optionales **eigenständiges Befundimportformat** von bereits extern ermittelten Modellläufen: `case_engine.py import-jlens` übernimmt Modell, Experiment, Baseline, konkrete Intervention und passende Kontrollbedingung mitsamt Report-Hash. Daten bleiben ausdrücklich `user_supplied_external_not_replicated_here`. Ohne eine tatsächlich vorhandene, berechtigte lokale Laufzeit wird kein J-Lens-Prozess gestartet, kein Host umkonfiguriert und keine neuronale Wirkung behauptet. Eine echte Anwendung kann bei explizitem Forschungsauftrag die dokumentierten `/api/*`-Originalschnittstellen des Tools prüfen und danach vergleichbare Befunde importieren.

**Nicht verwechselt:** eine Theorie, eine ausführbare Fremdimplementierung, unser eigener übertragener Mechanismus und dessen tatsächliche Testabdeckung sind vier verschiedene Dinge. Jeder der drei Repos ist sachlich integriert, aber nicht jeder lässt sich in eine Skills-only-ChatGPT-Laufzeit vollständig verpflanzen. Wer später vollständige J-Lens-Steuerung verlangt, braucht eine separate ausdrücklich beauftragte lokale Modellintegration.
