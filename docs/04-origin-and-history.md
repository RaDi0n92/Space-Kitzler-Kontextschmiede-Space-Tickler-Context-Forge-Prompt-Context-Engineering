# Origin and development history

## English

### Reconstructed origin

The surviving project record says the work began as a prompt-engineering specialist: create new prompts, improve existing prompts, and assess how well they fit their task. The project then focused on a more demanding practical problem: turn long, evolving conversations, decisions, documents, and research into an immediately usable prompt or a context handoff that a later agent could independently verify.

The original ChatGPT project conversation itself was not accessible during this documentation work. The account below is a reconstruction from surviving handoff notes, package documents, and the current live plugin. It does not claim to be a complete transcript.

### Main turns in the product's development

1. **From prompt crafting to context work.** The product expanded from prompt quality into recovering a project's intent and history well enough to support the next piece of work.
2. **Correction of the “plugin factory” detour.** A period of work treated the product as a tool for creating plugins. The user corrected this: plugin building is a distinct, optional specialist job; it is not the central mission.
3. **More freedom for the next agent.** A handoff should preserve original sources and meaningful corrections while letting the next agent read, interpret, and discover independently. The idea of 18 possibilities was intended to signal richness, not 18 required routines.
4. **Research has to change the work.** Research references are useful only when they influence source choice, interpretation, a test, or a real deliverable. Naming a method or adding more words is not evidence of improvement.
5. **Source identity became a defining product rule.** A ChatGPT project, a VPS document, a local file, a summary, and an agent log are different sources. If an original cannot be opened, the gap must be stated rather than filled in from memory.
6. **German product identity and skills.** The user selected the visible name **Space-Kitzler-Kontextschmiede** and asked for German skill names. The current live package now contains one German main skill and 17 German specialist skills.
7. **Preserve the product and verify the actual package.** A concern that the interface showed only one skill led to a complete paginated read of the live file list. The complete inventory contains 18 active skill files.
8. **Keep release claims evidence-based.** The live plugin is at 0.10.0. A previous handoff notes that the reason for not using 1.0.0 was the lack of a demonstrated end-to-end host test; the current package work did not change the release.

### Collaboration history that shaped the product

The user repeatedly corrected drift from the requested source or outcome: look for the requested ChatGPT project conversation rather than substitute VPS or agent records; do not turn a request into another plan when implementation is authorized; do not infer that all skills exist from an incomplete first page; and do not report a change without reading the result back.

The resulting working expectation is concrete: use the user's named source first, state exact access limits, preserve corrections and earlier failed interpretations, carry out the requested deliverable, and verify the artifact. The user's request for persistence and high standards is represented as observable follow-through and evidence, not as claims about an assistant's feelings or hidden internal state.

### Date and version landmarks

- **Earlier project phase:** prompt-engineering specialist and long-context handoff ideas; exact dates and full session chronology are not available in the originals here.
- **Historical package docs:** include early design iterations, including versions 0.2 through 0.8-era material and an archived v0.7 library.
- **17 October 2026:** current release 0.10.0 was attached according to Plugin Creator metadata.
- **19–20 October 2026:** surviving handoff and live-abnahme notes recorded the product's history, limitations, full 18-skill verification, and open host checks.
- **21 October 2026:** current private plugin identity and archive were verified again; repository contents are being prepared from that live release.

The user's earlier message named 0.9.4 as the starting point for renewed work. That was not the live release when checked; the verified current release is 0.10.0.

### What this history does not claim

It does not claim to have reopened the original project session, read the VPS plan files in this turn, or reconstructed every older chat. It does not treat prior assistant summaries as originals. An exact chronology should be extended only after the original project conversation and VPS sources become accessible.

## Deutsch

### Rekonstruierter Ursprung

Die erhaltene Projektdokumentation beschreibt den Ausgangspunkt als Prompt-Engineering-Spezialist: neue Prompts erstellen, vorhandene Prompts verbessern und ihre Eignung für die Aufgabe beurteilen. Danach verlagerte sich der Schwerpunkt auf ein anspruchsvolleres praktisches Problem: lange, fortschreitende Gespräche, Entscheidungen, Dokumente und Forschung in sofort nutzbare Prompts oder Kontextübergaben zu überführen, die ein späterer Agent selbst überprüfen kann.

Die originale ChatGPT-Projektunterhaltung war während dieser Dokumentationsarbeit nicht erreichbar. Der folgende Bericht ist aus erhaltenen Übergaben, Paketdokumenten und dem aktuellen Live-Plugin rekonstruiert. Er beansprucht kein vollständiges Transkript.

### Wichtige Wendungen der Produktentwicklung

1. **Vom Promptbau zur Kontextarbeit.** Das Produkt entwickelte sich von Promptqualität hin zur Wiedergewinnung von Projektabsicht und Verlauf, damit die nächste Arbeit sinnvoll anschließen kann.
2. **Korrektur des Umwegs „Pluginfabrik“.** Zeitweise wurde das Produkt als Werkzeug zum Erstellen von Plugins verstanden. Der Nutzer korrigierte dies: Pluginbau ist eine getrennte, optionale Fachaufgabe und nicht die zentrale Mission.
3. **Mehr Freiheit für den nächsten Agenten.** Eine Übergabe soll Originalquellen und wichtige Korrekturen bewahren und dem nächsten Agenten zugleich ermöglichen, selbst zu lesen, zu deuten und Neues zu entdecken. Die Zahl 18 stand für Reichhaltigkeit, nicht für 18 vorgeschriebene Routinen.
4. **Forschung muss die Arbeit verändern.** Forschungsreferenzen sind nur dann nützlich, wenn sie Quellenauswahl, Deutung, Prüfung oder ein echtes Arbeitsergebnis beeinflussen. Eine Methode zu benennen oder mehr Text hinzuzufügen ist kein Verbesserungsbeleg.
5. **Quellenidentität wurde zur Produktregel.** ChatGPT-Projekt, VPS-Dokument, lokale Datei, Zusammenfassung und Agentenlog sind verschiedene Quellen. Wenn ein Original nicht geöffnet werden kann, muss die Lücke benannt werden, statt sie aus dem Gedächtnis zu füllen.
6. **Deutsche Produktidentität und Skills.** Der Nutzer wählte den sichtbaren Namen **Space-Kitzler-Kontextschmiede** und wünschte deutsche Skillnamen. Das aktuelle Livepaket enthält nun einen deutschen Hauptskill und 17 deutsche Fachskills.
7. **Produkt bewahren, tatsächliches Paket prüfen.** Die Sorge, dass die Oberfläche nur einen Skill zeige, führte zur vollständigen paginierten Prüfung der Live-Dateiliste. Das vollständige Inventar enthält 18 aktive Skill-Dateien.
8. **Release-Aussagen an Belege binden.** Das Live-Plugin steht auf 0.10.0. Eine frühere Übergabe hält fest, dass 1.0.0 wegen eines fehlenden Ende-zu-Ende-Hosttests zurückgestellt wurde; die aktuelle Repository-Arbeit hat den Release nicht verändert.

### Zusammenarbeit, die das Produkt geprägt hat

Der Nutzer korrigierte wiederholt Abweichungen von der gewünschten Quelle oder dem gewünschten Ergebnis: die benannte ChatGPT-Projektunterhaltung suchen, statt sie durch VPS- oder Agentenunterlagen zu ersetzen; einen Umsetzungsauftrag nicht in einen weiteren Plan verwandeln; nicht aus einer unvollständigen ersten Dateiseite auf fehlende Skills schließen; und keine Änderung melden, ohne das Ergebnis erneut zu lesen.

Daraus folgt eine konkrete Arbeitserwartung: zuerst die benannte Quelle verwenden, genaue Zugriffslücken angeben, Korrekturen und frühere Fehlinterpretationen erhalten, das beauftragte Ergebnis herstellen und das Artefakt prüfen. Der Wunsch des Nutzers nach Ausdauer und hohen Standards wird als sichtbares Weiterarbeiten und Belege umgesetzt, nicht als Behauptung über Gefühle oder verborgene Innenzustände eines Assistenten.
